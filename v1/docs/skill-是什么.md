# Skill 是什么、怎么开发（用 ai-eyes 当例子）

> 写给不熟悉 skill 机制的人。看完你应该能回答：它凭什么会被触发、它和普通脚本差在哪、怎么改、怎么验证。

## 一句话

**Skill = 一份写给 agent 的说明书（`SKILL.md`）+ 它需要用到的文件与命令。**
模型不会“安装”你的代码，它只是在需要的时候读到这份说明书，然后照着去调用你的程序。

## 一个 skill 最小长什么样

```text
skills/ai-eyes/
└── SKILL.md          ← 必需，就这一个文件也能算 skill
```

`SKILL.md` 开头必须有一段 frontmatter：

```yaml
---
name: ai-eyes
description: 按名字/进程/句柄捕获 Windows 窗口，返回带 capture_id 的截图证据；
  用于“看一眼这个窗口/页面/报错”，并把视觉结论绑定到证据。
---
```

- `name`：技能名，要和目录名一致。
- `description`：**最重要的一行**。agent 平时看不到正文，只看到这一行；它决定了“什么时候想起你”。
  写清两件事：这技能能做什么 + 什么场景该用它（自然语言里的触发词一起写进去）。

正文就是给 agent 的操作手册：什么时候用、什么时候不用、命令怎么写、输出什么、必须遵守什么规则。

## 它和“写个工具”有什么区别

普通工具：用户要自己在终端敲命令。
Skill：**agent 自己决定要不要用**，并且知道怎么用、用错了怎么退。

所以正文里真正重要的不是“功能列表”，而是：

1. **决策信息**：什么时候用我、什么时候别用我（`ai-eyes` 里写明：网页内容优先用 browser-skill）。
2. **调用契约**：命令、参数、JSON 字段、退出码（`0/2/3/4` 各自什么意思）。
3. **失败怎么退**：歧义要问用户、最小化要提示还原、黑图要报“独占全屏”。
4. **硬规则**：`ai-eyes` 的四条（同轮证据、引用可见、时间新鲜、矛盾必报）。

## 装到哪里、怎么被加载

- 用户级：`C:\Users\<你>\.dsh\skills\<name>\SKILL.md`（所有人会话可用）
- 项目级：项目里的技能目录（只在该项目可用）
- 本项目就是这么装的：`C:\Users\18907\.dsh\skills\ai-eyes\SKILL.md`

加载发生在**会话开始**（或目录变化）时；装完在技能清单里出现，agent 需要时用 `skill` 工具读全文。
所以：**写的时候像写文档，跑的时候像写代码** —— 文档决定“会不会被用”，代码决定“用得对不对”。

## ai-eyes 的分层（为什么这么拆）

```text
SKILL.md            → 给 agent 看：怎么选窗口、怎么引用、四条硬规则
rival_eye/eyes.py   → 干活：枚举窗口、PrintWindow 截图、CLI
rival_eye/evidence.py → 记账：capture_id、sha256、索引、latest
scripts/verify_evidence.py → 裁判：回答有没有真看图（零模型规则）
tests/              → 保证改动没把上面弄坏
```

好处：说明书可以随便改文案，不影响代码；代码可以重构，不影响 agent 的用法契约。

## 修改 skill 的安全流程

1. 改 `SKILL.md`：只动正文，先别动 frontmatter 的 `description`（改了会影响触发，需要重新验证）。
2. 改代码：跑测试 `python tests\test_eyes.py`（11 项）。
3. 跑一次真实调用：`capture --process <某个窗口> --json`，确认 JSON 字段没变。
4. 重新装：把 `v1\skills\ai-eyes\SKILL.md` 复制到 `~\.dsh\skills\ai-eyes\SKILL.md`。
5. 新会话里说一句触发词（“看一眼这个窗口”），看它会不会主动用。

## 常见坑

- **description 写太虚**（“强大的截图工具”）→ 永远不被触发。要写场景和触发词。
- **正文写实现细节**（类名、函数名）→ agent 记不住也用不上，写“做什么、怎么调、失败怎么办”。
- **命令依赖当前目录** → 换个 cwd 就断。所以 `ai-eyes` 改成绝对路径调用，并加了 `doctor` 自检。
- **没有验收标准** → 改坏了也不知道。所以有测试 + `verify_evidence.py` 的 PASS/UNGROUNDED。

## 一句话总结

Skill 开发 = **把“什么时候用、怎么用、用完怎么证明没用错”写清楚**，再配一个能被命令行调用的实现。
文档质量决定它会不会被用，代码质量决定它靠不靠得住。
